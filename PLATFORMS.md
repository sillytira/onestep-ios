# OneStep 0.3 beta

Core use requires no server, internet connection, or account. iOS remains native SwiftUI with its Live Activity; Android, Windows, and Linux share a Flutter Material 3 client. Platform projects are deterministically generated by `node portable/tool/bootstrap.mjs` after installing Flutter 3.38.5. Source is under `portable/lib`; run `flutter pub get`, `flutter analyze`, and `flutter test` there. Platform build workflows run on the appropriate operating systems.

## Names

- Apple main ID: `meow.tira.onestep`; extension: `meow.tira.onestep.liveactivity`.
- Android package: `meow.tira.onestep`.
- Windows display name: OneStep; executable: **Tira-OneStep.exe**; application identity: `meow.tira.onestep`.
- Linux desktop/application ID: `meow.tira.onestep`; executable: `onestep`; x86-64 AppImage.

The new iOS ID is a separate sandbox. **Do not delete the old app.** First install the `migration-bridge` IPA over the existing app using the same signing settings as before. It retains `tech.sillycat.onestep` and adds export. Open Settings → Backups, Wi-Fi transfer, and accounts → Export backup. Install the normal new-ID IPA, import that file, and verify your data before removing anything. The bridge and normal app each include a Live Activity extension, so free-account App ID/app limits still apply. If both cannot coexist, export to Files first, verify the backup on another device, and manage signing slots through your installer. Never remove the old app until the backup is safely saved.

## Local transfers

Both devices must be on the same private IPv4 LAN. On the sender open Data and devices/Your space, confirm its local IP, create a pairing code, then copy the code privately to the receiver. Keep both apps/screens open. The receiver previews the snapshot before explicitly replacing its planner. Every import saves a recovery copy, accessible in Data tools. Import stops transferred focus timers. This is **manual snapshot transfer**, not continuous bidirectional sync or automatic conflict resolution. Export both devices before combining separate edits.

The pairing URI contains a randomly generated 256-bit AES-GCM key in its fragment. The network request authenticates with a SHA-256-derived bearer token; the key is not sent in the request. The response is nonce(12 bytes), ciphertext, tag(16 bytes). Transfers expire after 10 minutes, stop when leaving the sender screen/backgrounding, and accept only private IPv4 receiver endpoints. No discovery/relay/central service. Treat the code like a temporary password. A profile copied by pairing is a local identity, not proof that someone owns a hosted account.

JSON backups contain readable personal data; LAN payloads are encrypted. Backups/recovery files rely on the device/user-account storage protections. Custom full-database encryption and app PIN protection have not been implemented.

## Hosted sign-in, optional

No hosted project has been created or deployed automatically. To enable shared online email-code identity:

1. Create a Supabase Free project in your own account. The hosted dashboard is the admin interface; no VM or home server is needed.
2. Enable email authentication, and change the email template to include `{{ .Token }}` rather than relying on a magic-link redirect. Configure delivery for your intended users: the default Supabase email sender is restricted and rate-limited, so a public multi-user launch needs a supported SMTP provider. See https://supabase.com/docs/guides/auth/auth-smtp and https://supabase.com/docs/guides/auth/auth-email-passwordless .
3. In each client enter the HTTPS project URL and **publishable** or legacy **anon** key. Never enter service-role/secret keys in the app, source, or chat. The service verifies the email code and returns the same user UUID on different devices.
4. The app saves that UUID as a local profile; it does **not** upload planner data, keep an authenticated background session, or implement cloud sync. Tokens are not persisted. Reverify when needed. Renaming or importing a local profile cannot grant backend privileges.

Free hosting has quotas and can pause inactive projects; it is not an uptime guarantee. Sign-in needs internet, but planner use and LAN transfers do not.

## Platform reminders and packages

- Android: allow notifications and precise alarms in settings. The app falls back to inexact alarms if precise access is denied. Device power policies can delay alerts. Reboot receiver restores scheduled alerts; reopen to extend the 14-day / 60-alert scheduling window. This first APK uses a CI beta signing identity cached between builds. Cache expiry can change it; permanent private release signing must be configured before promising seamless Android updates. Export before updating. The generator supports ONESTEP_KEYSTORE, ONESTEP_STORE_PASSWORD, ONESTEP_KEY_ALIAS, ONESTEP_KEY_PASSWORD for private signing; never commit the key.
- Windows: extract the complete distribution ZIP, then run Tira-OneStep.exe. Keep the DLL/data folders together. Allow local networking only on your private network when prompted. Unsigned binaries may produce a Windows reputation prompt. Banners require OS notification support and OneStep to remain running.
- Linux: x86-64 AppImage built on Ubuntu 22.04, requiring a compatible desktop with GTK 3 and system notification support. `chmod +x OneStep-0.3.0-x86_64.AppImage` then launch. `--appimage-extract-and-run` works without FUSE where supported. Desktop timers/banners do not run after app exit.
- iOS: sign the IPA with your installer, retaining the extension. Free Apple signing expiry and provisioning limits still apply. Ordinary notifications are used. Time Sensitive provisioning is a separate unresolved device/signing check. No critical-alert override.

## Product direction, not shipped functionality

The design direction is a dark rounded-card layout with distinct blue/violet/green accents, readable balances/progress, account details, and transaction-style history. Original assets and native platform controls are used; no third-party screenshots or branding are bundled.

Proposed rewards: completing tasks earns points; points cannot be purchased with real money; points may redeem app time. A future backend must own an append-only points ledger with authenticated, audited admin adjustments and idempotent award/reversal events. Clients must not be trusted to submit arbitrary balances. Public rankings must be opt-in and contain only a selected display name and score, not private tasks, email addresses, or app-usage details. Reward amounts, time prices, task verification, offline reconciliation, parent approval, and ranking periods remain to be specified. The progress count in the portable beta is **not spendable points**.

iOS app shielding requires Family Controls authorization, entitlements and an appropriate Apple signing/distribution path. It is not enabled in this free-signed beta. A parent PIN inside OneStep cannot replace Screen Time authorization or make the app uninstall-proof. The separate optional points “banking” application is a future proposal; it does not involve real-money accounts.

Native iOS code changes still require installing/resigning a new IPA. An in-app release check can locate packages but cannot replace the executable or extend Apple's signing profile.
