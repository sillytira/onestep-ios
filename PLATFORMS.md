# OneStep 0.5 platform and service architecture

Main iOS: native SwiftUI, deployment iOS 26+, intended for iPhone 12, one WidgetKit Live Activity extension. Main bundle ID meow.tira.onestep; extension meow.tira.onestep.liveactivity. Source models preserve schema 1 JSON compatibility. The historical old-ID bridge exists only for safe export/migration.

Android: Material 3, minimum API 24, meow.tira.onestep. Notifications use native Android alarms; precision depends on permission. Windows: native x64 Flutter distribution, display OneStep, executable Tira-OneStep.exe with bundled DLL/data files. Linux: x86-64 AppImage built on Ubuntu 22.04, compatible GTK3 desktop and credential/notification services required. Desktop reminders need the app running; no background daemon is installed.

Bank/Kids/Parent phone companions use the same Flutter service views with role-specific IDs and names. The actual server account kind controls privileges, not the compiled app role. Each app's secure storage is isolated, so the user signs in/configures the service on each app. There is no shared keychain entitlement/App Group dependency.

The offline planner uses local versioned documents and encrypted manual LAN snapshots. AES-GCM transfer wire is 12-byte nonce + ciphertext + 16-byte tag; a random 256-bit pairing secret stays in the invitation fragment while a derived bearer authenticates the request. Sender expires after 10 minutes and stops on background/exit. LAN receivers accept private IPv4 targets and reject redirects. This is not automatic sync. Backups/recovery copies are readable JSON and never include authentication sessions.

Optional hosted services use Supabase Auth and PostgreSQL RLS/RPCs. Clients default to the configured main OneStep instance. Only the approved publishable client key and main-instance URL are embedded. Privileged project keys and owner enrollment secrets are excluded. Sessions/settings and account snapshots use Keychain/Flutter secure storage. Only explicitly assigned family tasks go online; private planner data is not uploaded automatically. Backend migration files 001–004 define an audited points ledger, opt-in rankings excluding Kids, family/task approval, beta enrollment triggers, reserved names, immutable account kinds, admin controls, and parent-only unlink/offline-verifier setup. FAMILY.md contains the full flow.

Account creation requires a single-use admin-issued beta key. The service is configured without email confirmation for this beta. A privately bound owner invite creates the owner grant; email alone never confers privilege. Runtime passwords/tokens and plaintext enrollment/parent-code material must never be logged, put in Notion, committed, or included in public source packages. The public client key is intentionally shipped with user authorization. Admin adjustments are append-only bounded ledger events, not arbitrary client balance assignments. App administration does not reveal raw DB credentials or expose unrestricted SQL.

The managed free service needs no VPS/home server. Full self-hosted Supabase currently lists minimum 2 CPU cores / 4 GB and recommends more; a 1-core / 4-GB VM is more appropriate to a small custom service than the full stack. No paid hosting is provisioned by these workflows. Managed Free projects can pause when inactive, and quotas/rate limits apply. Verify current provider documentation before changing hosting.

Build toolchain: Node 22, Flutter 3.38.5, Xcode 26.6 for native/macOS builds, Java 17 for Android, platform desktop toolchains. Flutter secure storage 9.2.4 adds Linux libsecret/jsoncpp dependencies. pubspec.lock is retained. Public source scanning and behavior/permission tests run in Actions; role-specific native/package checks precede artifact upload. No Apple signing credentials or private release keystore is committed.
