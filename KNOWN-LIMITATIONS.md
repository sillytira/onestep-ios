# OneStep 0.7 beta limitations

- Physical installs, phone reminder delivery, retained data after updates/migration, actual phone-to-PC LAN transfer, and offline parent-code behavior on real devices still require acceptance checks. CI/simulator results are not those device results.
- Core planner use is offline. Online enrollment, family linking, task submission/approval, profile/ranking changes, and admin adjustments need the hosted service. Account snapshots are labeled with last sync; a missing snapshot is shown as unknown, not zero. Portable service views poll about every 20 seconds while open; native Bank has manual refresh. No guaranteed instant background delivery.
- Kids identity is email-only and rankings exclude it server-side. A child cannot unlink itself. Parent authorization gates ordinary device sign-out, but signing out does not remove the server family relationship. Only a linked parent can unlink. Parent codes must be set up and synced before offline use; rotations reach offline devices only when they reconnect. Repeated guesses are locally rate-limited. This cannot prevent uninstall, reset, clearing app data, a modified client, or a compromised OS.
- Family invitations establish a trusted-family application link, not verified age/legal guardianship or Apple authorization. Actual shielding and app-time redemption are implemented only in the separately provisioned native Screen Time variant; physical-device authorization/expiry acceptance remains pending. Critical Alerts are not implemented. Parent codes cannot replace OS-level parental controls.
- Points are virtual and not purchasable. Parent-assigned family tasks earn their fixed reward once after approval; ordinary private planner tasks award only after explicit enrollment and server checks. These are bounded self-reports, not proof of real-world work. See REWARDS.md for caps and exclusions.
- App admin UI provides account/balance inspection, invitation generation, and audited point adjustments. It does not provide DB passwords, service-role keys, unrestricted SQL/schema/billing controls, or every Supabase dashboard feature. An owner account was visibly present in Auth Users; credentials were not entered by Codex. Real multi-client owner/family acceptance remains pending. Email confirmation is deliberately disabled; possession of a bound invitation proves enrollment authorization, not email ownership. Password-reset email delivery is not configured or promised by this beta.
- The public connection is built in; account sessions are entered at runtime and stored by OS secure storage. A locked/unavailable desktop credential service can prevent online account use; the offline planner still works. Secure-storage/device migration across reinstalls is not guaranteed. Backups/imports contain only planner data and cannot grant roles, mint points, or transfer sign-in sessions.
- Main iOS uses ordinary local notifications and one Live Activity extension. Up to 60 alerts look 14 days ahead; reopen to refill. Notifications obey permissions, Focus/silent settings, and device policy. No critical override, guaranteed Time Sensitive provisioning, APNs, or unlimited background execution. An opt-in private next-action widget and shared App Group exist only in the separately provisioned Screen Time variant. Shortcut widgets reuse the existing extension. Live Activity Done/Snooze is implemented; signed-device checks remain pending. On iPhone 12, Live Activities use the Lock Screen. Time Sensitive routine alerts activate only if the signed app and system settings allow them; ordinary alerts are the fallback. Countdown rendering is system-driven; other content updates on app use.
- Android exact-alarm/notification permissions and power policies affect reminders. Desktop timers/banners need the app running and OS notification support. Sleep/exit suspends them. One focus timer supports up to 8 hours; duration timers pause/resume, fixed iOS finish times do not move. Portable UI offers durations.
- Simple daily/weekly task recurrence advances after completion without missed-date backlog. Advanced recurrence and folders/tags remain future work. Routine Undo for today, today-only time changes, and portable guided-sequence progression are implemented.
- Wi-Fi uses encrypted foreground private-IPv4 snapshot transfer with explicit replacement/recovery, not continuous merging, discovery, IPv6-only support, or online planner sync. Export both devices before combining separate edits. JSON exports/recovery are readable private data; keep them private.
- New Apple meow.tira.onestep identity cannot share the old tech.sillycat.onestep sandbox automatically. Use the old-ID bridge to export before migrating. Never delete the only planner copy. Free Apple signing expiry, app/App-ID limits, extension signing, and native-IPA reinstall requirements remain. Install only needed companion roles per device.
- The delivered 0.5 Android APKs are signed with a saved permanent private key. Their certificate differs from unrecoverable 0.4 test keys, requiring a one-time safe backup/migration for old Android installs. Raw CI test-signed artifacts must be re-signed before official delivery unless repository signing secrets are configured. Windows is an unsigned portable bundle requiring its DLL/data files. Linux targets compatible x86-64 GTK3 desktops, not every architecture/distribution.

- Version 0.5 content updates fetch public, bounded data from the fixed OneStep GitHub feed. They do not replace native code. Automatic checks can be disabled; valid cached packs remain available offline. Adding a pack is explicit and does not overwrite personal edits.
- Parent/account enrollment, physical-phone behavior, private widget data sharing, and OS app shielding are implemented but remain conditional or require user/device/Apple action; they have not been reported as completed by content updates.
